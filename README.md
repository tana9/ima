# ima

今していることを Google カレンダーの専用カレンダーに記録する、Google Apps Script の Web アプリです。

## 主な機能

- 作業の内容・場所・メモを入力して開始し、前の作業を自動終了
- 終了日時の直接指定や、分単位での加算・減算
- 今日の記録の表示・編集・削除
- 最近使った内容からの入力
- 画像の添付と現在地の入力

記録先は `ima` という名前のカレンダーです。同名のカレンダーがなければ自動作成します。
添付画像は Google Drive の `ima` フォルダに保存します。

## 使い方

1. 公開したWebアプリを開き、作業の内容を入力します。場所・メモ・画像は任意です。
2. 「開始する」を押して確認すると記録を開始します。進行中の作業があれば自動終了します。
3. 作業を終えるときは「終了する」欄で終了日時を指定して終了します。未入力の場合は現在時刻を5分単位で切り上げます。
4. 記録を修正したい場合は、今日の一覧から編集します。

開始時刻は5分単位で切り捨てます。例えば10:03に開始すると10:00、10:17に終了すると既定値は10:20になります。

## 構成

ビルドやフロントエンドの依存パッケージは不要です。Apps Script の HTML テンプレートで各ファイルを読み込みます。

| ファイル | 役割 |
| --- | --- |
| `Taskfile.yml` | テスト、認証、ソース反映、デプロイなどの操作 |
| `scripts/preview.cjs` | ローカルプレビュー用HTTPサーバーとテンプレート展開 |
| `scripts/preview-mock.js` | プレビュー専用のサンプルデータとGoogle通信の代替処理 |
| `scripts/preview-controls.html` | 表示状態の切り替えと保存時の自動更新 |
| `playwright.config.cjs` / `tests/browser/` | デスクトップ・スマートフォンの実ブラウザテスト |
| `src/Index.html` | 画面のHTMLと各ファイルの読み込み |
| `src/Styles.html` | CSS |
| `src/DateTime.html` | ブラウザのローカル日時の変換・計算・検証。DOMと通信に依存しない |
| `src/Api.html` | `google.script.run` のPromise化と共通のエラー表示 |
| `src/State.html` | 画面状態、編集下書き、読み込み、操作ロックの管理 |
| `src/App.html` | 状態を表示する処理とユーザー操作 |
| `src/Code.gs` | カレンダー・Drive操作、画面全体のデータ取得、テンプレート配信 |
| `src/DateValidation.gs` | 本番サーバー・ブラウザ・プレビューで共有する日時の丸め・期間検証 |
| `src/appsscript.json` | Apps Scriptの設定と必要な権限 |

状態・今日の記録・候補一覧は `getDashboard()` でまとめて取得します。古いリクエストの結果は破棄します。
画面に影響する非同期操作は `runAction()` を通し、確認中・処理中の二重操作を防ぎます。
開始・保存に失敗した場合は入力を残し、再読み込みしても編集中の下書きを保持します。

終了欄の日時は端末のローカル時刻です。サーバーにはミリ秒のタイムスタンプを送ります。
開始時刻は現在時刻を5分単位で切り捨てます（例: 10:01 → 10:00、10:05:00 → 10:05）。開始時刻は記録の編集で変更できます。
終了時刻の既定値は現在時刻を5分単位で切り上げます（例: 10:01 → 10:05、10:05:00 → 10:05）。未入力で終了する場合と「現在時刻を入力」、未入力からの時間加減算に適用し、直接指定した日時はそのまま使用します。
前のタスクは新しい開始時刻で自動終了します。ただし、前の開始時刻以下になる場合は従来どおり最低1分の長さを確保します。
明示的に指定した終了日時が開始日時以前の場合は、記録を変更せずエラーを表示します。
記録の編集で時刻を変更していない場合は、表示されない秒・ミリ秒も保持します。
「今日」の一覧は Apps Script プロジェクトのタイムゾーン（Asia/Tokyo）を基準にします。

## ローカルプレビュー

デプロイせずに画面を確認するには、次のコマンドを実行し、ブラウザで `http://127.0.0.1:3000` を開いてください。Node.jsとTaskだけで起動でき、Googleへのログインは不要です。

```sh
task preview
```

`src/` のHTML・CSS・JavaScriptやプレビュー専用ファイルを保存すると、約1秒でブラウザが自動更新されます。画面上部の「自動更新を一時停止」で、操作中の入力を保ちながら編集できます。「自動更新を再開」を押すと未反映の変更も適用します。終了は端末で `Ctrl+C` を押します。ポートを変更する場合は `task preview PORT=3001` を実行してください。

画面上部で次の状態を切り替えられます。選択した状態はURLに保存され、自動更新後も維持します。

| 表示状態 | 確認できる内容 |
| --- | --- |
| 進行中 | 終了済みと進行中の記録、終了欄 |
| 記録なし | 空の一覧と新しい作業の開始 |
| 長いタイトル | 長文の折り返しと狭い画面での表示 |
| 通信エラー | 初回読み込みの失敗と「再読み込み」による復旧 |

本番と同じ画面にサンプルデータを表示し、開始・終了・編集・削除を試せます。データはページ内のメモリだけに保持し、再読み込みで初期状態に戻ります。実際のカレンダーやDriveには保存しません。
日時の丸め・期間検証・自動終了の最低時間は `DateValidation.gs` の共通処理を使用します。本番ブラウザには `includeDateRules_()` で同じ処理を配信し、サーバー側でも検証します。
画像はファイル選択まで確認でき、保存操作では未対応のメッセージを表示します。現在地の取得にはブラウザの位置情報の許可が必要です。Googleの認証・保存処理やサーバー側の `Code.gs` の動作確認にはApps Scriptのテスト用Webアプリを使用してください。

## テスト

Node.js と Task で実行します。テスト用の外部パッケージは不要です。

```sh
task test
```

日時の境界条件、入力検証、通信失敗、二重操作、応答順の逆転、編集下書きの保持を確認します。
テスト名と、入力・期待値に使う文言、モックのエラーメッセージは日本語で記述します。
単体テストではGoogleサービスとDOMをモックに置き換えます。

画面操作の検証には [Playwright](https://playwright.dev/docs/test-webserver) を使用します。初回に依存パッケージとChromiumを準備し、次のタスクを実行してください。

```sh
task setup:browser
task test:browser
```

デスクトップとスマートフォン相当の画面サイズで、開始・編集・終了・削除、表示状態の切り替え、入力検証、通信エラーからの復旧、保存時の自動更新と一時停止を確認します。
テスト用サーバーはポート3100で自動起動し、終了時に停止します。単体テストとブラウザテストをまとめて実行する場合は `task test:all` を使用してください。
失敗時は `test-results/` にスクリーンショットとトレースを保存します。Googleの認証や実際のカレンダー・Driveへの保存はApps Script環境で別途確認してください。

## 開発・デプロイ操作

操作はリポジトリ直下の `Taskfile.yml` にまとめています。[Task](https://taskfile.dev/docs/installation) と Node.js 22以降（npm・npxを含む）を用意してください。
Apps Scriptの操作には [clasp 3系](https://github.com/google/clasp) をnpx経由で使用します。初回実行時にはパッケージのダウンロードが必要です。

| コマンド | 操作 |
| --- | --- |
| `task` | 操作一覧の表示 |
| `task test` | テストの実行 |
| `task setup:browser` | ブラウザテスト用の依存パッケージとChromiumを準備 |
| `task test:browser` | 実ブラウザで画面操作を検証 |
| `task test:all` | 単体テストと実ブラウザテストを実行 |
| `task preview` | ローカルプレビューを起動（既定ポート3000） |
| `task login` | Googleアカウントでの認証 |
| `task status` | 反映対象ファイルの確認 |
| `task push` | テスト成功後にソースを反映 |
| `task deployments` | デプロイIDと公開バージョンの確認 |
| `task deploy DEPLOYMENT_ID=対象のデプロイID` | テスト・ソース反映・既存デプロイの更新 |
| `task deploy:new` | テスト・ソース反映・新規デプロイの作成 |
| `task open` | Apps Scriptエディタを開く |

初回は `task login` で認証し、[Apps Scriptの設定](https://script.google.com/home/usersettings)でApps Script APIを有効にします。
反映先は `.clasp.json` の `scriptId`、反映するソースの場所は `rootDir`（`src`）で指定しています。

通常の更新では `task deployments` で対象のIDを確認し、次のコマンドを実行します。

```sh
task deploy DEPLOYMENT_ID=対象のデプロイID
```

既存デプロイを更新するため公開URLを維持できます。`task push` だけではバージョン指定の公開内容は更新されません。
初めて公開する場合は `task deploy:new` を使い、Webアプリの実行ユーザーやアクセス範囲はApps Script側で設定します。
デプロイ処理は順番に実行し、テストやソース反映が失敗した場合はそこで停止します。

画像添付には `DriveApp` が必要とする `drive` スコープを使用しています。以前の `drive.file` から切り替えた後は、利用時に権限の再承認が必要です。
添付画像はリンクを知っている人が閲覧できる設定で保存します。
